# Design: #228 versioning.yml template schema does not match erd's expected format

## Architecture Overview

The fix adds backward-compatible support for the legacy `branches: [{prefix, bump}]` template format in `tag_config.rs`, while keeping the existing `versioning.branch_prefixes` format as the canonical schema. This is achieved through a custom serde deserialization that detects which format is present and normalizes to the internal `BranchPrefixes` struct. The template and workflow comments are also updated to document the correct format.

## Problem Analysis

Two incompatible YAML schemas exist for `versioning.yml`:

### Format A — Template format (WRONG, generated by `plugin.sh`)
```yaml
branches:
  - prefix: "major/"
    bump: major
  - prefix: "release/"
    bump: minor
default_bump: rc
```

### Format B — Code-expected format (CORRECT, `tag_config.rs`)
```yaml
versioning:
  branch_prefixes:
    major:
      - "major/"
    minor:
      - "release/"
    patch:
      - "feature/"
```

Because `Config` uses `#[serde(default)]` on all fields, Format A loads successfully but produces empty `BranchPrefixes`, causing all branches to match as `BumpType::Rc`.

## Interface Design

### Approach: Custom Deserialize for Config (Option 1 from issue)

Add support for both formats at the `Config` deserialization level. When `branches` key is detected at root level, convert it to the canonical `BranchPrefixes` structure.

### New Internal Types

| Name | Purpose |
| --- | --- |
| `LegacyBranchRule` | Represents a single `{prefix, bump}` entry from the template format |
| `LegacyConfig` | Represents the root-level `branches` + `default_bump` template format |
| `RawConfig` | Untagged enum that serde tries to match against both formats |

### Type Definitions

```rust
/// A single branch rule in the legacy template format
#[derive(Debug, Deserialize)]
struct LegacyBranchRule {
    prefix: String,
    bump: String,
}

/// Legacy config format used by the template
#[derive(Debug, Deserialize)]
struct LegacyConfig {
    branches: Vec<LegacyBranchRule>,
    #[serde(default)]
    default_bump: Option<String>,
}
```

### Conversion Strategy

Rather than using `#[serde(untagged)]` enum (which produces poor error messages), implement a two-pass deserialization:

1. First, attempt to deserialize as the canonical `Config` format
2. Check if the result has empty branch prefixes AND the raw YAML contains a `branches` key
3. If so, attempt to deserialize as `LegacyConfig` and convert

Alternatively (simpler approach): Add `branches` and `default_bump` as optional fields on `Config` itself, then in a post-deserialization step, merge them into `BranchPrefixes` if the canonical fields are empty.

### Recommended Approach: Flattened Config with post-processing

```rust
#[derive(Debug, Deserialize, Default)]
pub struct Config {
    #[serde(default)]
    pub versioning: VersioningConfig,

    // Legacy template format support
    #[serde(default)]
    branches: Vec<LegacyBranchRule>,
    #[serde(default)]
    default_bump: Option<String>,
}
```

After deserialization, if `versioning.branch_prefixes` is empty but `branches` is non-empty, convert the legacy format:

```rust
impl Config {
    fn normalize(mut self) -> Self {
        if self.versioning.branch_prefixes.is_empty() && !self.branches.is_empty() {
            self.versioning.branch_prefixes = BranchPrefixes::from_legacy(&self.branches);
        }
        self
    }
}
```

### Public API Changes

| Name | Change | Description |
| --- | --- | --- |
| `Config::load_from_file` | Modified | Calls `normalize()` after deserialization |
| `Config::load_from_default` | Modified | Calls `normalize()` after deserialization |
| `BranchPrefixes::is_empty` | New | Returns true if all prefix vectors are empty |
| `BranchPrefixes::from_legacy` | New (private) | Converts legacy `branches` rules to canonical format |
| `LegacyBranchRule` | New (private) | Serde struct for legacy format entries |

## Data Flow

1. User's `versioning.yml` is read as a string
2. `serde_yaml::from_str()` deserializes into `Config` (with both canonical and legacy fields)
3. `Config::normalize()` checks if legacy fields are populated and canonical fields are empty
4. If so, legacy `branches` entries are iterated and sorted into `BranchPrefixes.{major,minor,patch,release}` based on the `bump` field
5. `match_branch()` operates on the normalized `BranchPrefixes` as before

## Error Handling

- **Unknown bump type in legacy format**: Log a warning and skip the entry (e.g., `bump: "unknown"` is ignored)
- **Both formats present**: Canonical format takes precedence (legacy fields are ignored if `branch_prefixes` is non-empty)
- **Empty config**: Continues to default to all-RC behavior (existing behavior preserved)
- **`default_bump` field**: Acknowledged but not used — the default RC behavior is hardcoded in `match_branch()` and matches the typical `default_bump: rc` template value

## Implementation Notes

- **Backward compatibility**: Existing projects using the template format will work without changes after the code fix
- **Forward compatibility**: New projects will get the correct format from the updated template
- **No migration needed**: Both formats are supported simultaneously
- **Legacy fields are private**: `branches` and `default_bump` are not part of the public API
- **`default_bump` is informational only**: Since RC is already the hardcoded default, this field has no functional effect, but we accept it to avoid deserialization errors on existing configs
- **Warning on legacy format**: Consider printing a deprecation warning to stderr when legacy format is detected, to encourage migration
